# Test plan

## Principles

- Tests are written before production code (see [AGENT_RULES.md](AGENT_RULES.md)).
- Every acceptance test in [ACCEPTANCE_TESTS.md](ACCEPTANCE_TESTS.md) maps to
  one or more executable tests; the test name carries its ID, e.g.
  `AT-07 rejects processing -> approved`.
- Mocks are used only for isolation. External providers are replaced by
  test doubles **only** in tests that verify our handling of provider
  behaviour; a feature that depends on a provider is not reported as done
  until a real adapter exists and has passed a live contract check.

## Layers

| Layer | Location | Runner | What it covers |
| --- | --- | --- | --- |
| Unit | `tests/unit` | `bun test` | Domain rules, state machines, validators, truth rules, template logic. No I/O. |
| Integration | `tests/integration` | `bun test` | Real migrations on SQLite (`bun:sqlite` D1 adapter), repositories, API handlers invoked through the Worker `fetch`, storage port with in-memory object store, generation service with provider test doubles. |
| Security | `tests/security` | `bun test` | Tenant isolation, auth/session, CSRF, rate limits, upload rejection, signed URL forgery/expiry, download authorisation, safe errors, security headers. |
| E2E | `tests/e2e` | Playwright | Real browser against `wrangler dev` (workerd + local D1/R2). Primary journey: sign in → property → photos → campaign → generate → review → approve → download pack. |

## Test infrastructure

- `tests/support/sqlite-d1.ts` — D1-compatible adapter over `bun:sqlite`;
  applies every file in `migrations/` in order with foreign keys on.
- `tests/support/app.ts` — builds a Worker `Env` with the SQLite DB, an
  in-memory object store implementing the storage port, a test queue that
  records messages, and a fixed signing secret.
- `tests/support/fixtures/` — real, minimal image files (valid and malformed)
  generated byte-for-byte in code so no binary fixtures are needed.

## Commands

```bash
bun run test            # unit + integration + security
bun run test:unit
bun run test:integration
bun run test:security
bun run test:e2e        # requires built app; starts wrangler dev
bun run typecheck
bun run lint
bun run build
```

## CI

`.github/workflows/ci.yml` runs install → typecheck → lint → unit →
integration → security → build (→ E2E once the journey exists). A failing
step fails the pipeline; no step is allowed to be skipped or marked
`continue-on-error`.

## Provider contract checks

Each real provider adapter gets a contract test in
`tests/integration/providers/<name>.live.test.ts` that runs only when its
credentials are present (`LB_LIVE_PROVIDER_TESTS=1`). These are the only
conditionally-run tests and they are reported explicitly in
CURRENT_STATUS as "live contract: not run" when credentials are absent. They
never count as proof that a feature works when they did not run.
